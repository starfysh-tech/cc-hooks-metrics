Architecture

What's inside

Report sections
  • Bash layer hook-metrics.sh wraps every hook with /usr/bin/time -p. db-init.sh owns the SQLite schema. audit-logger.sh captures tool use.
  • Python report hooks_report/ — Rich 14.3.3 for terminal rendering. static.py renders 14+ sections. advisor.py generates tuning suggestions.
  • OTel export spans.py + otlp.py — zero external deps. Full OTLP/HTTP JSON. Deterministic trace IDs from session.
  • Storage ~/.claude/hooks.db — SQLite with busy_timeout. hook_metrics + audit_events tables. 1% probabilistic pruning > 30 days.
  • Semantic exit codes codex-review, pytest, vitest — exit 1 means findings, not failure. Tracked separately in reporting.
  • Privacy Host SHA256[:12]. Path basenames only. SQL injection prevention via _sql_escape. Stderr capped at 200 bytes.
Commands

One script, many views

hooks-report.sh Traffic lights, waterfall, action items, trends, guardrails
--verbose Adds perf table, WoW summary, top projects, reliability, repo dashboard
--export OTel-aligned JSON — pipe to analysis tools or Claude
--export-spans OTLP span JSON — ship to Jaeger, Grafana, Honeycomb
--step guard-security Drill into a specific hook step
--sessions Recent Claude Code sessions ranked by overhead
--export | claude -p "..." Pipe telemetry to Claude for natural-language analysis
